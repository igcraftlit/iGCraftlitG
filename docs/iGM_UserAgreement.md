# iGCraftLit 用户管理规定

本规定适用于所有访问、注册、使用 iGCraftLit Community（以下简称“本社区”）服务的用户。本规定以中文版本为准，其他语言版本仅为方便用户理解。

---

## 第一篇 总则与基本理念

### 第一章 目的与依据

#### 第一节 制定目的

iGCraftLit Community（以下简称“本社区”）是面向所有探星者的开放社区。为维护社区秩序，保障全球用户权益，明确用户行为规范，促进社区健康、有序、可持续发展，特制定本规定。

#### 第二节 法律依据与国际准则

本规定依据中华人民共和国相关法律法规，并参照国际通行准则制定。用户在使用本社区服务时，应遵守所在地法律法规及国际公认的法律准则。本社区不隶属于任何国家或政治实体，用户须自行遵守所在地法律。

#### 第三节 适用范围

本规定适用于所有访问、注册、使用本社区服务的用户，包括但不限于浏览、发帖、评论、上传资源、下载资源、使用 CLI 与 API 等行为。用户继续使用社区服务即视为同意本规定。

### 第二章 基本理念

#### 第一节 梦想

我们因梦想而聚。每一位探星者都带着对未知的好奇与对未来的向往。本社区尊重并鼓励用户追求梦想，在社区中表达自我、分享热情、寻找同行者。

#### 第二节 创造

我们因创造而强。本社区鼓励用户创作内容、开发工具、搭建实例、上传资源。无论是模组、材质包、地图还是整合包，每一次创造都是社区成长的基石。

#### 第三节 探索

在探索中前行。本社区鼓励用户探索新技术、新玩法、新领域。通过 CLI、API、适配器协议等工具，用户可深入探索 Minecraft 生态与更广阔的技术世界。

#### 第四节 创新

在创新中突破。本社区支持用户提出新想法、尝试新方案、解决新问题。创新是社区保持活力的源泉，也是我们走向未来的动力。

#### 第五节 求真

以求真之心共建社区。本社区倡导真实、客观、理性的交流氛围。用户应尊重事实，避免传播虚假信息，以真诚态度参与社区互动。

### 第三章 全球共处原则

#### 第一节 多元包容

本社区倡导全球共处、多元包容。来自不同国家、地区、民族、文化背景的探星者，均可在本社区平等交流。任何形式的歧视、偏见与排外言论均不被允许。

#### 第二节 平等交流

所有用户在社区中享有平等的表达权与参与权。禁止因国籍、种族、性别、宗教、地域、语言等差异攻击、侮辱或贬低他人。

#### 第三节 文化尊重

用户应尊重不同文化、宗教信仰与风俗习惯。在跨文化交流中，应以理性、克制、友善为底线，避免因文化差异引发冲突。

#### 第四节 国际社区定位

本社区立足国际背景，面向全球用户，致力于打造一个跨越国界、多元共存、平等交流的全球性社区。我们鼓励用户以开放心态参与国际交流，共同维护良好的社区氛围。

## 第二篇 账号与身份

### 第四章 注册与账号创建

#### 第一节 分步注册流程

本社区采用分步注册机制，共分为五步：基础信息填写、密码设置、阅读并同意《iGCraftLit 用户管理规定》、位置验证、邮箱验证码验证。用户须逐步完成，每一步通过校验后方可进入下一步。

#### 第二节 用户名与邮箱规范

1. 用户名须唯一，长度 3 至 20 位，支持中英文与数字，不可包含特殊符号。
2. 邮箱须真实可用，格式校验通过，且不可与已有用户重复。
3. 禁止使用冒充官方、误导他人、侵犯他人权益的用户名与邮箱。

#### 第三节 密码安全要求

1. 密码长度必须大于 6 位。
2. 密码须至少包含两种字符类型：大写字母、小写字母、数字、特殊符号。
3. 用户应妥善保管密码，不得向他人透露。
4. 建议定期更换密码，避免与其他平台使用相同密码。

#### 第四节 位置验证与 IP 查询

1. 注册时采用免费、可商用的 IP 定位服务获取用户粗略位置，包括国家、地区、城市。
2. 用户须同意授权系统查询其 IP 地址，用于账户安全、区域统计与合规审查。
3. IP 查询结果仅用于上述目的，不会用于广告推送或未经授权的第三方共享。
4. 位置信息记录到用户档案，用户可随时在账户设置中查看。
5. 若定位失败，允许用户手动选择国家与地区。
6. 用户不得伪造位置信息或使用代理工具规避所在地法律法规。

#### 第五节 用户管理规定确认

1. 用户须完整阅读《iGCraftLit 用户管理规定》。
2. 阅读页面须滚动到底部，方可勾选“我已阅读并同意《iGCraftLit 用户管理规定》”。
3. 勾选并点击“已完成阅读，选择遵守规定”后，方可进入下一步。
4. 同意记录将写入 iGM_UserAgreements 表，包含版本与时间。

### 第五章 iGMUid 系统

#### 第一节 11 位唯一标识

iGMUid 是每位用户在社区中的唯一认证值，由系统自动分配，共 11 位数字，全局唯一。其结构为「1 位区分位 + 10 位全局顺序号」。

#### 第二节 生成规则

1. iGMUid 共 11 位数字。
2. 第 1 位为区分位，用于标识账号类型：
   - 0：管理员、官方人员
   - 1 至 8：普通用户
   - 9：测试账号
3. 后 10 位为全局顺序号，从 1 开始，按注册顺序递增，全局唯一，不使用 0 作为顺序号。
4. 预置账号：
   - 网站最高管理者：属于测试账号，序列号为 1，iGMUid 为 `90000000001`。
   - iGCraftLit 组织所有者：序列号为 1，iGMUid 为 `10000000001`。
   - MuoCeon 组织所有者：序列号为 2，iGMUid 为 `10000000002`。
5. 普通用户注册时，从序列号 3 开始分配，区分位为 1 至 8。
6. 测试账号区分位为 9，除最高管理者外，其他测试账号序列号从 2 开始。
7. 顺序号一经分配不可更改，用户不可指定或修改。
8. 生成规则由后端统一控制，按区分位分别记录当前最大顺序号，保证不重复。
9. iGMUid 一经生成，不可修改、不可转让，用户不得自行指定或更改区分位。

#### 第三节 使用场景

1. 用于社区内的身份识别与认证。
2. 用于组织认证、权限分配、操作日志。
3. 用于 API Key 绑定、CLI 登录、下载记录同步。
4. 用于管理员用户管理界面的身份展示。

#### 第四节 不可修改性

iGMUid 是用户的永久标识，不随用户名、邮箱、认证状态变化而变化。用户不得以任何理由要求修改或重新分配 iGMUid。

### 第六章 账号安全与管理

#### 第一节 账号归属

账号归 iGCraftLit 所有，用户享有使用权。用户不得主张账号所有权，亦不得将账号用于非法用途。

#### 第二节 密码保管

1. 用户须妥善保管密码，因密码泄露造成的损失由用户自行承担。
2. 用户发现账号异常时，应立即通过邮箱重置密码并联系管理员。
3. 社区不会以任何形式主动索要用户密码。

#### 第三节 禁止转让、出租、售卖

1. 禁止以任何形式转让、出租、售卖账号。
2. 禁止共享账号给他人使用。
3. 违反者视情节轻重予以警告、禁言、封禁、永久封禁，最高予以删除账号处置。

#### 第四节 异常登录处理

1. 系统检测到异常登录时，可触发邮箱提醒或强制下线。
2. 用户可通过账户设置查看登录记录与设备信息。
3. 多次异常登录的账号，管理员有权暂时冻结并联系用户核实。

#### 第五节 账号注销与删除

1. 用户可主动申请注销账号，注销后账号数据将被匿名化或删除。
2. 因严重违规被永久封禁的账号，管理员有权直接删除。
3. 注销或删除后，iGMUid 不再重新分配，相关记录保留用于合规与审计。

## 第三篇 社区行为规范

### 第七章 基本行为准则

#### 第一节 尊重他人

1. 用户应尊重其他用户的人格、观点、劳动成果与隐私。
2. 禁止人身攻击、侮辱、诽谤、威胁、骚扰、恶意挑衅。
3. 禁止因国籍、种族、性别、宗教、地域、语言等差异歧视或贬低他人。
4. 鼓励理性表达不同意见，但不得以攻击性方式针对他人。

#### 第二节 理性讨论

1. 用户应基于事实与逻辑参与讨论，避免情绪化争吵。
2. 禁止发布煽动对立、制造矛盾、恶意引战的言论。
3. 对存在争议的话题，应保持克制，尊重不同立场。
4. 管理员有权对偏离主题、扰乱讨论秩序的内容进行干预。

#### 第三节 遵守法律

1. 用户须遵守所在地法律法规及国际公认的法律准则。
2. 禁止利用本社区从事任何违法活动。
3. 禁止发布、传播、存储违反法律的内容。
4. 用户须自行承担因违法行为产生的一切后果。

#### 第四节 维护社区秩序

1. 用户应共同维护社区的正常秩序与良好氛围。
2. 禁止恶意举报、滥用举报功能、干扰管理员正常履职。
3. 禁止冒充管理员、版主、组织负责人或官方人员。
4. 发现违规行为可通过举报入口反馈，不得私自处理。

### 第八章 内容发布规范

#### 第一节 发帖与评论

1. 发帖须选择正确的分类与标签，标题应清晰描述内容。
2. 评论须与主题相关，不得发布无意义内容。
3. 禁止发布重复内容、跨版块刷帖、恶意顶帖。
4. 发帖与评论须遵守本规定第九章禁止内容的要求。

#### 第二节 图片与附件

1. 上传图片须符合格式、大小、数量限制。
2. 禁止上传违法、色情、暴力、侵权、恶意图片。
3. 附件须为社区允许的文件类型，禁止上传可执行脚本伪装文件。
4. 用户须确保上传内容不侵犯第三方知识产权。

#### 第三节 标签与分类

1. 用户应合理使用标签与分类，便于内容检索与推荐。
2. 禁止滥用标签、添加无关标签、恶意占用热门标签。
3. 管理员有权调整、合并、删除不合理的标签与分类。

#### 第四节 禁止刷屏与灌水

1. 禁止短时间内大量发布相同或相似内容。
2. 禁止在评论、私信、通知中重复发送无意义信息。
3. 禁止利用脚本、工具自动刷帖、刷评论、刷点赞。
4. 违反者视情节轻重予以警告、禁言、封禁处理。

### 第九章 禁止内容

#### 第一节 色情与低俗内容

1. 禁止发布、传播、存储色情、淫秽、低俗、性暗示内容。
2. 禁止发布涉及未成年人性内容。
3. 禁止发布带有性骚扰、性侮辱性质的言论或图片。
4. 违反者视情节轻重予以 30 天封禁、永久封禁，最高予以删除账号处置。

#### 第二节 暴力与恐怖内容

1. 禁止发布、传播、存储暴力、血腥、恐怖、残忍、自杀自残内容。
2. 禁止发布煽动暴力、恐怖主义、极端主义的内容。
3. 禁止发布涉及虐待动物、虐待他人的内容。
4. 违反者视情节轻重予以 30 天封禁、永久封禁，最高予以删除账号处置。

#### 第三节 仇恨与歧视内容

1. 禁止发布煽动仇恨、歧视、民族对立、宗教冲突的内容。
2. 禁止发布针对特定国家、种族、性别、宗教、地域的攻击性内容。
3. 禁止发布美化战争、恐怖主义、极端主义的内容。
4. 违反者视情节轻重予以 30 天封禁、永久封禁，最高予以删除账号处置。

#### 第四节 虚假与诈骗内容

1. 禁止发布虚假信息、谣言、误导性内容。
2. 禁止发布诈骗、传销、非法集资、非法广告。
3. 禁止冒充官方、组织、他人发布虚假通知。
4. 违反者视情节轻重予以 30 天封禁、永久封禁，最高予以删除账号处置。

#### 第五节 侵权与隐私侵犯

1. 禁止侵犯他人隐私、肖像权、名誉权、知识产权。
2. 禁止未经授权发布他人个人信息、聊天记录、照片。
3. 禁止未经授权转载、抄袭他人原创内容。
4. 违反者视情节轻重予以 7 天禁言、30 天封禁、永久封禁，最高予以删除账号处置。

#### 第六节 恶意代码与网络攻击

1. 禁止发布病毒、木马、外挂、恶意代码、网络攻击工具。
2. 禁止利用社区服务进行网络攻击、扫描、入侵、数据窃取。
3. 禁止发布破解、盗版、规避正版验证的工具或教程。
4. 违反者视情节轻重予以 30 天封禁、永久封禁，最高予以删除账号处置，并保留配合执法机关调查的权利。

#### 第七节 未成年人保护

1. 禁止发布涉及未成年人隐私、色情、暴力、虐待的内容。
2. 禁止诱导、教唆未成年人从事违法或危险行为。
3. 禁止向未成年人传播不适宜内容。
4. 违反者视情节轻重予以 30 天封禁、永久封禁，最高予以删除账号处置，并保留配合执法机关调查的权利。

## 第五篇 组织认证与信任体系

### 第十二章 组织体系

#### 第一节 组织类型

1. 本社区的组织分为两类：受信任组织与普通组织。
2. 受信任组织由 iGCraftLit 与 MuoCeon 共同认定，享有社区认证标识与审核权限。
3. 普通组织须经申请审批后方可创建，享有基础组织功能，但不具备审核权限。
4. 普通组织在满足条件后，可申请升级为受信任组织。

#### 第二节 受信任组织

1. iGCraftLit 是本社区的创始组织，负责社区整体运营、规则制定、技术开发，拥有最高管理权限。
2. MuoCeon 是本社区的联合组织，参与社区建设、资源贡献、活动运营，与 iGCraftLit 享有同级认证标识。
3. 受信任组织可审核本组织的认证申请，可维护组织介绍，可推荐优质资源。
4. 受信任组织负责人邮箱分别为：igcraftlit@outlook.com、cayihuo@outlook.com。

#### 第三节 普通组织

1. 普通组织的创建采用申请审批制。已注册用户须提交组织创建申请，经管理员审核通过后，方可正式创建普通组织。
2. 普通组织须填写组织名称、简介、负责人、联系方式。
3. 普通组织不具备认证审核权限，成员不自动获得认证标识。
4. 普通组织可申请升级为受信任组织，由 iGCraftLit 与 MuoCeon 共同审核。

#### 第四节 组织负责人

1. 每个组织设有负责人，负责本组织的申请审核、介绍维护、成员管理。
2. 负责人只能审核自己组织的申请，不能审核其他组织的申请。
3. 负责人不能审核自己的申请。
4. 负责人的认证标识在个人主页、帖子、评论、顶部导航中显示。
5. 负责人若违规，由管理员直接处理。

### 第十三章 组织创建与加入

#### 第一节 创建组织

1. 组织创建采用申请审批制，只有提交申请并通过审核的用户，方可创建组织。
2. 用户可在组织页面提交创建申请，填写组织名称、简介、负责人、联系方式。
3. 组织名称须唯一，不得冒充官方、受信任组织或他人。
4. 提交后由管理员审核，审核通过后组织正式成立。
5. 创建者自动成为该组织负责人。

#### 第二节 加入组织

1. 用户可浏览组织列表，选择目标组织提交加入申请。
2. 加入申请由该组织负责人审核。
3. 审核通过后，用户成为该组织成员，获得组织成员标识。
4. 受信任组织的成员可获得对应组织的认证标识。

#### 第三节 退出组织

1. 成员可在组织详情页底部点击“申请退出”。
2. 退出后，成员标识与认证标识移除，组织相关权限收回。
3. 退出后可重新申请加入。
4. 因严重违规被撤销认证的用户，限制重新申请。

#### 第四节 组织解散

1. 组织负责人可申请解散组织。
2. 解散前须处理成员关系、资源归属、未完成事务。
3. 受信任组织的解散须经 iGCraftLit 与 MuoCeon 共同审核。
4. 解散后，组织数据保留用于审计，成员标识移除。

### 第十四章 组织认证申请

#### 第一节 申请条件

1. 申请者须为已注册并登录的社区用户。
2. 申请者须选择目标组织，包括受信任组织与普通组织。
3. 申请者须填写申请理由，可选上传证明材料。
4. 同一用户同一时间只能有一个待审核申请。

#### 第二节 申请流程

1. 用户进入组织认证申请页面，选择目标组织。
2. 填写申请理由，上传证明材料（可选）。
3. 提交申请后，进入待审核状态。
4. 用户可查看申请状态与历史记录。
5. 待审核期间，用户可取消申请后重新提交。

#### 第三节 审核机制

1. 受信任组织的申请由对应组织负责人或管理员审核。
2. 普通组织的申请由该组织负责人审核。
3. 负责人只能审核自己组织的申请，管理员可审核所有申请。
4. 审核人不能审核自己的申请。
5. 审核通过或拒绝时，须填写审核意见。
6. 审核结果通过站内通知与邮件通知申请人。

#### 第四节 认证标识

1. 审核通过后，用户获得对应组织的认证标识。
2. 受信任组织成员获得受信任认证标识，普通组织成员获得普通成员标识。
3. 认证标识在个人主页、帖子、评论、顶部导航中显示。
4. 认证标识不可伪造、转让、出租、售卖。
5. 认证标识与 iGMUid 绑定，可追溯、可撤销。

### 第十五章 组织升级与降级

#### 第一节 升级为受信任组织

1. 普通组织运营良好、成员活跃、资源优质、无违规记录的，可申请升级。
2. 申请须提交组织介绍、成员列表、运营数据、贡献说明。
3. 由 iGCraftLit 与 MuoCeon 共同审核，双方一致同意后方可升级。
4. 升级后，组织获得受信任标识与审核权限。

#### 第二节 降级与撤销

1. 受信任组织若长期不活跃、违规、损害社区声誉，可被降级或撤销。
2. 降级由 iGCraftLit 与 MuoCeon 共同决定。
3. 降级后，组织退回普通组织状态，成员认证标识调整。
4. 严重违规的，直接撤销组织资格，成员认证标识移除。

#### 第三节 组织介绍编辑

1. 组织负责人在组织成立后，可编辑本组织的“关于组织”内容。
2. 内容包括组织简介、愿景、联系方式、官网链接等。
3. 内容须真实、准确、合法，不得虚假宣传或误导他人。
4. 管理员有权对组织介绍内容进行审核与干预。

#### 第四节 负责人职责

1. 维护本组织的介绍内容与成员信息。
2. 审核本组织的加入申请，保证公正、客观、及时。
3. 代表本组织参与社区事务与活动。
4. 对严重违规成员有权撤销认证并上报管理员。
5. 负责人本人若违规，由管理员直接处理。

## 第七篇 通知、私信与社交

### 第十六章 通知系统

#### 第一节 站内通知

1. 站内通知用于提醒用户帖子被评论、评论被回复、活动报名成功、资源被下载、组织认证结果等事件。
2. 用户可在通知中心查看全部通知，支持按类型筛选、标记已读、全部已读、删除。
3. 未读通知数量在顶部导航与侧边栏实时显示。
4. 通知记录保留一定期限，超期自动清理。

#### 第二节 邮件通知

1. 邮件通知用于重要事件，如注册验证、密码重置、组织认证结果、好友申请、离线私信提醒。
2. 用户可在通知偏好设置中开启或关闭邮件通知。
3. 邮件内容根据用户控制台语言动态渲染，支持中英双语。
4. 邮件通过 iGM_MailService 发送，失败时重试并记录日志。

#### 第三节 通知偏好

1. 用户可分别设置站内通知与邮件通知的开关。
2. 用户可按事件类型单独控制，如评论、点赞、私信、活动、资源。
3. 通知偏好写入 iGM_NotificationPreferences 表，与账号绑定。
4. 未登录用户的偏好仅保存在本地，登录后同步至后端。

### 第十七章 私信与社交关系

#### 第一节 私信规范

1. 私信仅双方可见，管理员不可随意查看，仅在举报处理时按流程调取。
2. 禁止利用私信发送违法、色情、暴力、诈骗、骚扰、广告内容。
3. 禁止批量发送私信、恶意刷屏、骚扰他人。
4. 用户可撤回限时内发送的消息，可删除会话。
5. 黑名单用户不可发起私信。

#### 第二节 关注与好友

1. 用户可关注其他用户，查看其公开动态。
2. 好友关系须双方同意，可申请、同意、拒绝、删除。
3. 关注与好友列表默认公开，可在隐私设置中调整。
4. 禁止利用关注与好友功能进行骚扰、刷量、恶意营销。

#### 第三节 黑名单

1. 用户可将其他用户加入黑名单，阻止其关注、加好友、发私信、评论自己的内容。
2. 黑名单列表仅自己可见，可随时移除。
3. 被拉黑用户不会收到通知。
4. 管理员不介入普通用户之间的黑名单关系，除非涉及违规。

#### 第四节 隐私设置

1. 用户可设置个人资料的可见范围，如仅自己、仅好友、公开。
2. 用户可设置是否允许被搜索、是否显示在线状态、是否接收陌生人私信。
3. 隐私设置通过 iGM_UserPreferences 表保存。
4. 社区默认尊重用户隐私，不会公开敏感信息。

## 第八篇 资源上传与下载

### 第十八章 资源类型

#### 第一节 模组

1. 模组文件通常为 .jar，须标注支持的 Minecraft 版本与加载器。
2. 禁止上传恶意模组、破解模组、盗版模组。
3. 模组须遵守原作者许可协议。

#### 第二节 材质包

1. 材质包通常为 .zip，须包含 pack.mcmeta。
2. 禁止上传侵权、色情、暴力材质。
3. 须标注适用版本与分辨率。

#### 第三节 地图

1. 地图通常为 .zip 或文件夹，须包含 level.dat。
2. 禁止上传违法、侵权、恶意地图。
3. 须标注适用版本与游玩人数。

#### 第四节 整合包

1. 整合包通常为 .zip，须包含 manifest.json 或 modlist。
2. 须标注整合包版本、Minecraft 版本、加载器、模组列表。
3. 禁止上传未经授权转载的整合包。

#### 第五节 光影与皮肤

1. 光影包通常为 .zip，须标注适用加载器与版本。
2. 皮肤通常为 .png，须符合社区规范。
3. 禁止上传侵权、色情、暴力内容。

#### 第六节 插件与数据包

1. 插件通常为 .jar，适用于服务端。
2. 数据包通常为 .zip，适用于原版或模组环境。
3. 须标注兼容版本与平台。

### 第十九章 Minecraft 资源分区

#### 第一节 版本兼容

1. 资源须标注支持的 Minecraft 版本，可多选。
2. 用户可按版本筛选资源。
3. 版本不兼容时，启动器与网站提示用户。

#### 第二节 加载器支持

1. 资源须标注支持的加载器：Forge、Fabric、NeoForge、Quilt、原版、无。
2. 用户可按加载器筛选资源。
3. 启动器安装时自动校验加载器兼容性。

#### 第三节 平台支持

1. 资源须标注支持平台：Java 版、基岩版。
2. 不同平台资源分别展示与筛选。
3. 禁止将 Java 版资源标注为基岩版，或反之。

#### 第四节 许可协议

1. 上传者须选择或填写资源许可协议，如 MIT、GPL、CC、All Rights Reserved。
2. 禁止上传未注明许可协议的商业资源。
3. 社区尊重原作者许可协议，违规者将被删除资源并处罚。

#### 第五节 更新日志

1. 上传者可为资源添加更新日志，记录版本变化。
2. 更新日志按版本倒序展示。
3. 禁止在更新日志中发布广告、违法内容。

### 第二十章 上传与下载规范

#### 第一节 文件类型与大小

1. 允许的文件类型：.jar、.zip、.mcpack、.mcaddon、.png、.txt、.json 等。
2. 单文件大小限制可配置，默认不超过 100MB。
3. 禁止上传可执行脚本、病毒、木马、恶意文件。
4. 文件上传前须校验类型与哈希。

#### 第二节 版权与授权

1. 上传者须确保拥有资源版权或已获授权。
2. 禁止上传破解、盗版、规避正版验证的资源。
3. 禁止上传未经授权转载的商业资源、付费资源、独占资源。
4. 因版权纠纷产生的责任由上传者承担。

#### 第三节 下载与使用

1. 公开资源无需登录即可下载。
2. 私有资源或需登录的资源，须登录后下载。
3. 下载文件须校验哈希，防止损坏与篡改。
4. 用户不得将下载的资源用于违法用途。

#### 第四节 CLI 与 API 下载

1. 用户可通过 iGM CLI 下载资源，命令前缀 igm。
2. 用户可通过 iGM CLI Download API 下载资源，接口前缀 /api/igm-cli。
3. 下载过程支持断点续传、缓存、进度回调。
4. 第三方启动器可通过 SDK 或适配器协议接入下载能力。
5. 滥用下载接口、恶意爬取、转卖资源者，将被限制或封禁。

## 第九篇 违规处理与量化处罚

### 第二十一章 违规分级

#### 第一节 轻微违规

1. 初次无意违规，如误发无关内容、轻度灌水、标签误用。
2. 未造成明显不良影响。
3. 处罚：警告，或 1 天禁言。

#### 第二节 一般违规

1. 重复灌水、刷屏、恶意顶帖、轻度人身攻击。
2. 造成一定不良影响。
3. 处罚：3 天禁言。

#### 第三节 较重违规

1. 多次违规、恶意举报、侵犯隐私、轻度侵权。
2. 造成较坏影响。
3. 处罚：7 天禁言。

#### 第四节 严重违规

1. 发布色情、暴力、恐怖、仇恨、诈骗内容。
2. 发布恶意代码、网络攻击工具。
3. 造成严重不良影响。
4. 处罚：30 天封禁。

#### 第五节 特别严重违规

1. 触犯法律、危害社区安全、多次严重违规拒不改正。
2. 造成极坏影响。
3. 处罚：永久封禁，最高予以删除账号处置。

### 第二十二章 量化处罚

#### 第一节 警告

1. 适用于轻微违规。
2. 记录在案，累计多次升级处罚。
3. 警告记录保留一定期限。

#### 第二节 1 天禁言

1. 适用于轻微违规。
2. 禁止发帖、评论、私信 1 天。
3. 到期自动解除。

#### 第三节 3 天禁言

1. 适用于一般违规。
2. 禁止发帖、评论、私信 3 天。
3. 到期自动解除。

#### 第四节 7 天禁言

1. 适用于较重违规。
2. 禁止发帖、评论、私信 7 天。
3. 到期自动解除。

#### 第五节 30 天封禁

1. 适用于严重违规。
2. 禁止登录、发帖、评论、私信、下载 30 天。
3. 到期自动解除，但记录保留。

#### 第六节 永久封禁

1. 适用于特别严重违规。
2. 禁止登录、发帖、评论、私信、下载。
3. 不予解除，记录永久保留。

#### 第七节 删除账号

1. 适用于特别严重违规且触犯法律。
2. 账号数据删除或匿名化，iGMUid 不再分配。
3. 保留配合执法机关调查的权利。

### 第二十三章 处置依据与执行

#### 第一节 中华人民共和国相关法律法规

1. 违规行为若被管理员发现，将依照中华人民共和国相关法律法规及本规定进行处置。
2. 涉及违法犯罪的，保留移交司法机关的权利。
3. 用户须自行承担因违法行为产生的一切后果。

#### 第二节 管理员发现与处置

1. 管理员发现违规行为后，须记录证据、填写处置意见。
2. 处置须依据违规分级与量化处罚标准，不得随意加重或减轻。
3. 处置结果通过站内通知与邮件通知用户。
4. 用户可在规定期限内提出申诉。

#### 第三节 配合执法机关

1. 对涉嫌违法犯罪的，社区将配合相关国家或地区执法机关调查。
2. 依法提供必要的数据与日志。
3. 保留移交司法机关的权利。

#### 第四节 操作日志记录

1. 所有管理操作记录写入 iGM_AdminLogs 表。
2. 日志包含：管理员 ID、操作类型、目标类型、目标 ID、详情、时间。
3. 日志不可篡改，用于审计与申诉核查。

## 第十篇 举报、申诉与争议解决

### 第二十四章 举报机制

#### 第一节 举报入口

1. 用户可在帖子、评论、用户主页、私信、资源详情页找到举报按钮。
2. 举报须选择原因，可填写补充说明。
3. 举报人信息对普通用户不可见，仅管理员可见。

#### 第二节 举报受理

1. 管理员收到举报后，须在合理时间内受理。
2. 受理后，管理员核实证据，判断是否违规。
3. 举报处理结果通过站内通知告知举报人。
4. 恶意举报、虚假举报的，管理员有权对举报人处罚。

#### 第三节 举报处理

1. 违规内容将被删除，违规账号按量化处罚处理。
2. 不违规的举报，保留原内容，并告知举报人。
3. 举报处理记录写入 iGM_Reports 表。
4. 涉及严重违规的，上报最高管理者。

### 第二十五章 申诉与复议

#### 第一节 申诉条件

1. 用户对处罚有异议的，可在规定期限内提出申诉。
2. 申诉须提供理由与证据。
3. 同一处罚仅可申诉一次，特殊情况可申请复议。

#### 第二节 申诉流程

1. 用户通过申诉入口提交申诉。
2. 管理员复核证据与处置依据。
3. 复核结果通过站内通知与邮件通知用户。
4. 申诉成功的，撤销或减轻处罚。

#### 第三节 复议结果

1. 复议由更高层级管理员负责。
2. 复议结果为最终结果。
3. 复议记录写入操作日志。
4. 用户仍不服的，可向社区最高管理者反馈。

## 第十一篇 管理与运营

### 第二十六章 管理角色

#### 第一节 管理员

1. 管理员（admin）拥有社区最高权限。
2. 负责规则制定、用户管理、内容审核、组织审核、系统配置。
3. 管理员账号 iGMUid 以 0 开头。
4. 管理员不得滥用权限，须遵守管理规定。

#### 第二节 版主

1. 版主（moderator）负责内容审核、举报处理、日常秩序维护。
2. 版主由管理员任命，可被撤销。
3. 版主不得越权修改系统设置、用户角色。
4. 版主操作记录写入操作日志。

#### 第三节 组织负责人

1. 组织负责人负责本组织的成员审核、介绍维护、认证管理。
2. 负责人不得审核自己的申请。
3. 负责人违规由管理员处理。
4. 受信任组织负责人拥有与版主相近的内容审核权限，但限于本组织相关。

### 第二十七章 权限与职责

#### 第一节 权限分级

1. 权限分为：普通用户、组织负责人、版主、管理员。
2. 权限逐级提升，操作范围逐级扩大。
3. 权限分配记录写入操作日志。
4. 权限变更须由更高层级管理员执行。

#### 第二节 审核职责

1. 内容审核：删除违规内容、警告、禁言、封禁。
2. 组织审核：审核组织创建、加入、认证、升级、降级。
3. 举报处理：受理、核实、处置、反馈。
4. 审核须公正、客观、及时，不得徇私。

#### 第三节 数据统计

1. 管理员与版主可查看运营看板。
2. 看板包含用户增长、发帖量、评论量、活跃度、热门内容、资源下载排行、活动参与统计。
3. 数据仅用于运营决策，不得泄露用户隐私。
4. 看板访问记录写入操作日志。

#### 第四节 运营看板

1. 运营看板仅管理员与版主可访问。
2. 支持按时间范围查看趋势图表。
3. 支持导出统计数据，用于报告与审计。
4. 数据统计遵循隐私保护原则。

## 第十二篇 隐私与数据保护

### 第二十八章 数据收集与使用

#### 第一节 收集范围

1. 注册时收集：用户名、邮箱、密码哈希、IP 粗略位置。
2. 使用中收集：发帖、评论、上传、下载、登录记录、操作日志。
3. 技术数据：浏览器信息、设备信息、访问时间、Cookie。
4. 不收集与社区服务无关的敏感个人信息。

#### 第二节 使用目的

1. 提供社区服务、账号管理、内容展示、资源下载。
2. 保障账号安全、防止滥用、合规审查。
3. 统计分析、运营决策、产品改进。
4. 不用于广告推送、未经授权的第三方共享。

#### 第三节 数据存储

1. 用户数据存储于本地 SQLite 数据库。
2. 敏感数据加密存储，如密码哈希、令牌。
3. 数据保留期限依据服务需要与法律要求。
4. 账号注销后，数据匿名化或删除。

### 第二十九章 用户权利

#### 第一节 查看与修改

1. 用户可在账户设置中查看与修改个人资料。
2. 用户可查看登录记录、下载记录、积分记录。
3. 用户可修改密码、邮箱、隐私设置。
4. 修改记录写入操作日志。

#### 第二节 删除与导出

1. 用户可申请导出个人数据，格式为 JSON 或 CSV。
2. 用户可申请注销账号，注销后数据匿名化或删除。
3. 因违规被永久封禁的账号，管理员有权直接删除。
4. 删除或导出请求须在合理时间内处理。

#### 第三节 Cookie 与本地存储

1. 社区使用 Cookie 与 localStorage 保存登录状态、语言、主题、隐私偏好。
2. 用户可在浏览器中清除 Cookie 与本地存储。
3. 清除后，登录状态与偏好可能丢失，需重新设置。
4. 社区不会利用 Cookie 追踪用户跨站行为。
