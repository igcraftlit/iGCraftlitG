5.关于指令流程中 /metro summon 指令的执行逻辑，下列分析正确的是
A.该指令通过读取玩家手持物品的 station_id NBT 标签确定召唤站点，若玩家未手持含该标签的物品，矿车将在玩家脚下生成而
非站点位置
B.指令中 Passengers 字段挂载的盔甲架用于存储目的地信息，其 dest_id 值固定为3，说明该系统仅支持单向线路，无法实现多
站点调度
C. metro_timer 计分板用于记录矿车行驶距离，当数值达到 200 时触发到站检测，对应矿车在动力铁轨上以8m/s 速度行驶约 1600
米的距离
D.矿车生成后先被赋予 metro_new 标签用于初始化计时器，随后立即移除该标签，此设计可防止同一矿车被重复初始化，避免
计分板数据异常
6.关于 JAVA 路径计算代码与游戏机制的关联，下列说法正确的是
A. edgeWeight 使用 String 类型作为键（如"1-3"），其设计意图是利用字符串哈希的唯一性确保同一起终点对的权重不重复；若改
为 List<Integer>作为键，仍可保证唯一性且查询效率不变
B.代码中默认返回值 600 对应 30 秒，其计算依据是Minecraft 中 20tick=1 秒的基础时序；若动力铁轨加速后矿车实际速度为 12m/s，
则 600tick 内行驶距离应为360 米而非代码假设值
C. stationMap 声明为 Map<Integer, Station>但未在代码中初始化，这属于典型的空指针风险；在 Minecraft 数据包中，此类结构应改
用 data merge storage 指令替代 JAVA 集合
D.注释提示应使用 Dijkstra 算法，该算法适用于含负权边的图结构；若某段轨道因下坡加速导致"行驶时间"为负值，Dijkstra 算法
仍可正确求解最短路径
