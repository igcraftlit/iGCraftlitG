# 更新日志 · iGM CraftCeon Launcher

## 26.5.1 — 2026-10-18

### 新增
- **全局中英双语国际化（i18n）**：启动器全面接入 `next-intl`，界面文案不再有任何硬编码中文或英文残留。
  - 覆盖范围：侧边导航栏、首页、资源中心、服务器大厅、联机大厅、设置（通用 / 外观 / 关于）、
    所有弹窗提示、按钮文字与错误警告。
  - 语言包：完善 `messages/zh-CN.json` 与 `messages/en.json`，包含全部业务模块文案。
  - 语言切换入口：设置 → 通用 顶部新增【语言切换】（简体中文 / English），
    切换后整个启动器界面实时无刷新切换。
  - 持久化：语言选择保存到本地配置，下次启动依然生效。
- **联机大厅重构（完整开服闭环）**：与「视界」深度绑定，打通「开服 → 邀请 → 进服」完整流程。
  - 视界选择：顶部下拉框读取本地全部视界并显示绑定版本与加载器，作为联机房间的游戏目录。
  - 房主模式：选定视界后【创建联机房间】，先进入「正在建立 P2P 网络…」，
    成功后展示 6 位房间码与【复制】；提供【启动游戏并开服】与图文引导
    （进入游戏按 ESC 点击【对局域网开放】并记下端口），房主填写端口（默认 25565）后
    【绑定端口并等待加入】完成绑定。
  - 好友模式：输入 6 位房间码【加入房间】，先展示「正在连接…」，
    成功后展示「已成功加入房主的局域网」与【启动游戏】，并引导进入游戏点击【多人游戏】
    双击刷新出的局域网世界。
  - 底层双方案：主站在线时经主站 WebSocket 注册房间；主站离线时降级到 EasyTier 公共节点
    网络打洞；隧道转发 UDP 局域网广播包，让好友在多人游戏列表中直接刷出房间。

### 变更
- 版本号由 `26.5.0` 更新至 `26.5.1`（工程包、外壳、界面、Electrobun 配置与 Rust 核心同步）。
- 下载引擎统一 UA 由 `iGMLLauncher/26.5.0` 提升至 `iGMLLauncher/26.5.1`。

## 26.4.4 — 2026-10-18

### 新增
- **正版验证与社区账号解绑**：微软正版设备代码流授权不再要求先登录 iGCraftLit 社区账号，
  游客（未登录）同样可发起验证；验证通过的正版 Token、UUID 与皮肤头像统一落盘
  `launcher_data/accounts.json`。启动游戏时只校验当前选中账号是否具备有效正版凭证，
  不再强制校验社区账号绑定。
- **游客登录二次确认**：登录页「游客登录（跳过社区账号）」点击后弹出提示框，
  明确告知「游客登录产生的数据（如游玩记录、本地视界）将仅保存在当前设备，
  无法云同步或与社区生态互通」，提供【取消】与【继续】两个按钮，确认后才进入主界面。
- **历史社区账号快捷登录**：启动时读取本地 `accounts.json`，若存在历史社区账号记录，
  登录页直接展示该账号的头像与昵称，并提供【一键登录社区账号】按钮，
  直接复用长效令牌恢复登录态而无需重新走 OAuth 授权（令牌过期时回退为重新授权）。
- **服务器大厅（纯外部数据化）**：彻底废弃代码内写死的服务器清单，改为运行时经 Bun 主进程
  请求第三方公开服务器列表 API（携带 User-Agent），成功后写入本地缓存
  `launcher_data/servers_cache.json`，断网时降级读取缓存。
  支持在界面顶部【添加服务器】，填写名称 / IP / 端口 / 官网链接后落盘本地 SQLite
  `my_servers` 表并优先展示；状态查询统一由 Bun 进程请求 `mcsrvstat.us`（携带 UA）；
  【进入服务器】自动为游戏参数追加 `--server <ip> --port <端口>` 实现一键进服。

### 变更
- 版本号由 `26.4.3` 更新至 `26.4.4`（工程包、外壳、界面、Electrobun 配置与 Rust 核心同步）。
- 下载引擎统一 UA 由 `iGMLLauncher/26.4.3` 提升至 `iGMLLauncher/26.4.4`。
- **游客模式功能限制（防滥用）**：
  - 视界数量：游客最多创建 `2` 个本地视界，达到上限后再创建会被拒绝，
    并提示「游客模式最多创建 2 个视界，请登录社区账号解除限制」；
  - 下载通道：资源市场对游客仅开放「直连下载」，隐藏 SDK 通道，下载并发上限下调至 `4`；
  - 社区专属能力：未登录时隐藏社区专属菜单（更换头像 / 退出登录），
    右上角展示「游客」，点击引导前往登录页。

## 26.4.3 — 2026-10-18

### 新增
- **模组 / 资源下载路径选择**：资源市场点击「下载」后先弹出安装确认对话框，
  提供两种落盘方式——
  - **安装到视界**：下拉菜单列出全部已有视界，外壳自动把文件放入对应视界的
    `mods` / `shaderpacks` / `resourcepacks` / `modpacks` / `saves` 子目录；
  - **仅下载文件**：选择后提供目录选择器，由用户自选保存目录，文件直接落盘到该目录。
  相关契约：界面 → 外壳 `market:download` 扩展 `mode`（`horizon` / `folder`）、
  `horizonId` 与 `folderPath` 三个字段。
- **下载任务调度器**：任务管理器每行提供「暂停 / 继续 / 取消」三个操作按钮；
  暂停期间不再领取新文件、进度与速度冻结；取消会一并清理外壳侧临时缓存；
  任务全部到达终态后悬浮球自动消失。
- **游戏运行限速联动（核心）**：点击「启动游戏」且 Java 进程成功拉起后，启动器自动触发
  全局下载限速（`1 MB/s`）；任务管理器顶部常驻提示
  「检测到游戏运行中，已自动为您限制下载速度以防卡顿」；
  监听 Java 进程结束，游戏退出后自动解除限速、恢复全速下载。
  相关契约：外壳 → 界面 `download:throttle`（`{ active, bps, message }`）。
- **启动器自动更新系统**：启动时静默请求云端清单获取最新版本号，检测到更高版本即在
  右下角弹出极简更新提示（「发现新版本 vX.X.X」）；用户点击后由外壳后台静默下载更新包
  并实时回推进度，下载完成后提示「立即重启并更新」；「设置 → 关于」另提供「检查更新」按钮。
  相关契约：界面 → 外壳 `update:check` / `update:download` / `update:install`；
  外壳 → 界面 `update:state`。更新清单地址由 `IGM_LAUNCHER_V2_UPDATE_MANIFEST_URL` 覆盖。
- **外观与主题自定义**：设置页拆分为「通用 / 外观 / 关于」三个独立页签，新增「外观」页——
  - **背景模式**单选（两项）：`动态云背景` / `纯色背景`；
  - **动态云配色**三选（只改背景色调，不改 UI 主题色）：`经典深紫`（默认，深蓝与紫色交融）/
    `梦幻冷蓝`（冷蓝与青色交融）/ `极光幻粉`（深紫与粉色交融），切换后流体云实时变色；
  - **纯色背景**四选：`深邃暗黑` / `明亮浅色`（自动把界面文字与面板切换为深色以保证对比度）/
    `古典深咖` / `极光幽绿`；
  - **毛玻璃模糊度**滑动条（`0 - 30px`）：实时改写导航栏、卡片等元素的
    `backdrop-filter: blur(var(--igm-blur))`；
  - **主题色切换**：5 种预设（靛蓝 / 极光绿 / 樱花粉 / 极客黑 / 琥珀橙），
    同步更改整个启动器的按钮与高亮颜色（`--igm-accent` / `--igm-accent-soft` / `--igm-accent-wash`）。
  相关契约：界面 → 外壳 `appearance:get` / `appearance:set`；
  外壳 → 界面 `appearance:state`。配置落盘 `launcher_data/appearance.json`，启动时读取并应用。

## 26.4.2 — 2026-10-18

### 新增
- **游戏启动进度条**：启动游戏时弹出全屏居中的进度遮罩，按五个阶段推进并给出明确文案：
  `10%` 验证 Java 与依赖库 → `30%` 构建 JVM 参数 → `50%` 拉起 Java 进程 →
  `70%` 捕获到 `Setting user` / `Loading Minecraft` → `100%` 启动成功（遮罩自动关闭）。
  遮罩内同时列出阶段清单，已达成阶段高亮、未达成置灰。
  若外壳在 `stderr` 中捕获到严重报错（异常栈、`UnsupportedClassVersionError`、
  `Could not create the Java Virtual Machine`、`Unable to access jarfile` 等），
  立即中止进度推进并转为红色错误面板，面板内直接列出最近若干条错误日志，说明具体崩溃位置。
  相关契约：界面 → 外壳 `launch:progress`（查询当前进度）；
  外壳 → 界面 `launch:progress`（实时回推 `{ percent, stage, failed }`）。
- **资源市场**：资源中心内新增「资源市场」二级视图（与「游戏版本」并列切换），
  接入 Modrinth（免密钥）与 CurseForge（`IGM_CURSEFORGE_API_KEY`）双数据源，
  支持五类检索：模组、光影、材质包、整合包、地图。
  - **加载器筛选（核心）**：顶部筛选栏提供 `全部加载器 / Fabric / Forge / NeoForge`；
    选中即把过滤条件带进检索请求——Modrinth 以 `facets` 拼接（`categories:fabric` /
    `categories:forge` / `categories:neoforge`），CurseForge 以 `modLoaderType` 过滤
    （Fabric=4、Forge=1、NeoForge=6）；默认「全部加载器」不追加任何过滤条件。
    数据源侧另有 `classId` 分类映射（模组 6 / 材质包 12 / 整合包 4471 / 光影 6552 / 地图 17）。
  - 列表卡片展示图标、名称、作者、下载量与加载器标签（Fabric / Forge / NeoForge 分色），
    支持「加载更多」分页；点击卡片进入一卡式详情弹窗，展示简介、适用 MC 版本与下载文件信息。
  - Modrinth 请求统一携带 `User-Agent: iGMLLauncher/26.4.2 (contact: igcraftlit@outlook.com)`；
    CurseForge 请求携带 `x-api-key` 与 `Accept: application/json`。密钥仅主进程持有，不下发界面。
  - Modrinth 不提供地图分类，选择地图时自动切换数据源为 CurseForge。
- **资源双通道下载**：一卡式详情弹窗提供两个明确通道按钮——
  **通道 A：iGCraftLit SDK 下载**（由外壳后端代理转发）与
  **通道 B：直接下载**（下载引擎直连目标 URL 并自动调度源）。
  两条通道的任务统一进入右下角「任务管理器」，支持进度、速度与清空。
  外壳侧按所选通道确定首选地址，并把另一条通道作为自动回退候选（通道 A 代理不可用时回退直连，
  通道 B 直连不可用时回退代理），用户显式选择始终排在首位。
- 资源市场落盘规则：按分类写入当前视界的对应子目录（模组 `mods`、光影 `shaderpacks`、
  材质包 `resourcepacks`、整合包 `modpacks`、地图 `saves`），无可选视界时落入游戏根目录。

## 26.4.1 — 2026-10-18

### 新增
- 资源中心由「1 / 2 / 3 / 4 四步导航」重构为「一卡式安装弹窗」：点击任意版本卡片即在屏幕
  中心弹出一张卡片，在同一张卡内完成视界名称、加载器（vanilla / fabric / forge / neoforge）、
  加载器版本与存放路径四项配置，底部一个【开始安装】按钮直接开始下载，不再有分步流程。
- 一卡式安装弹窗新增【存放路径】行：文本输入框默认回填启动器当前根目录（如 `D:\iGML_Data`），
  右侧【浏览文件夹】按钮调用原生目录选择器；点击【开始安装】后外壳先按该路径生成标准
  `iGML_Matrix` 目录结构（`.minecraft` / `assets` / `libraries` / `versions` / `horizons` 等）
  再开始下载。外壳为此新增通用目录选择契约 `dialog:pick-folder` → `dialog:picked`
  （与安装向导的 `installer:browse` 分离，不再顺带改动设置）。
  **本条恢复了上一版被删除的「用户自选下载路径」能力，但只保留路径一项，下载源仍由引擎自动择优。**
- 下载源全自动择优：不再向用户暴露下载源选择，引擎在开始下载前于后台对三个源做
  延迟测速，按延迟升序排列候选源并自动选用最快者。
- 全自动源容灾 + 跨源断点续传：某一源在下载途中超时、过慢或返回非 206 时，引擎自动记录
  已完成分片并遍历下一可用源继续下载同一文件；仅在全部候选源都失败后任务才标记失败，
  全程无弹窗、无用户交互。**本条反转了上一版「超时弹窗由用户决定、绝不自动换源」的策略。**

### 修复
- **彻底修复自动扫描本机 Java 失效**：原实现扫描来源过窄（仅默认目录），且以 `java -version`
  的 **stdout** 解析版本——而 Java 的版本信息默认写入 **stderr**，导致扫到的条目版本号恒为空、
  被当成无效项丢弃。现重写扫描逻辑：
  - 扫描来源扩至五类：环境变量（`JAVA_HOME` / `JDK_HOME` / `JRE_HOME` 及 `PATH` 各段）、
    Windows 注册表（`HKLM` / `HKCU` 的 `JavaSoft` 各子键，含 `WOW6432Node` 32 位视图）、
    常见安装目录（Program Files 与 LOCALAPPDATA 下 Adoptium / Zulu / BellSoft / Corretto /
    Microsoft / Semeru / GraalVM 等，递归限深 5 层）、`where java` / `where javaw`、
    `.minecraft` 自带运行时（用户目录与启动器游戏根目录两处）。
  - 版本探测执行 `java -version` 时强制 `windowsHide: true`（消除黑框闪窗），
    **同时捕获 stdout 与 stderr** 并在合并文本上用三级正则解析（带引号 / 宽松 / 裸版本号），
    因此 `17.0.2` 与 `1.8.0_301` 两种形态均可正确识别。
  - 候选路径一律归一到 bin 目录内的 `javaw.exe`（缺失时回退 `java.exe`），
    按 bin 目录归一化去重，避免同一环境被多来源重复收录；单条候选探测失败只跳过该条。
  - 扫描结论无论成功与否都回推可读文案（检查位置数、新发现数、当前收录数、未解析数；
    零命中时明确列出已检查范围并指向手动添加），界面不再出现「点了没反应」。
  - 界面新增【手动添加 Java 路径】按钮（空列表时额外提供醒目入口）：调用原生文件选择器
    选取 `javaw.exe` / `java.exe`，走同一套版本解析逻辑，解析成功才入库并落盘
    `launcher_data/java.json`；文件名不符或版本无法解析时给出明确拒绝原因。
- **修复启动游戏时不按所选账号启动**：原实现无脑采用「已绑定正版优先」的硬编码分支，
  用户即使选中离线账号也会走正版分支并报「未找到正版凭据」。现改为**严格以设置中的
  `currentAccount` 为准**：未选择任何账号时直接拒绝并提示「请先选择要启动的账号」；
  正版分支读取 `microsoft.json` 的 `account.name` / `account.uuid` / `minecraftAccessToken`
  （超期先经微软刷新链续期）并注入 `--username / --uuid / --accessToken / --userType msa`；
  离线分支按 `currentAccount.id` 定位离线账号，使用 `OfflinePlayer:<昵称>` 推导的标准 UUID，
  注入 `--username / --uuid / --userType legacy` 与占位 `--accessToken 0`。
  启动小窗在未选账号时先行拦截并给出「前往账号中心」入口，视界按钮同时置灰禁用。
- **修复「未找到正版凭据」**：根因不是字段名不一致（落盘与读取字段名逐一对得上），而是
  上一版新增的「存放路径」功能在切换根目录时只把 `settings.json` 写入新目录，旧目录下的
  `microsoft.json`（正版凭据）、`offline.json`、`java.json` 与 `skins/` 被遗留为孤儿文件，
  导致读取路径指向新目录时读到空。现切换根目录后自动把旧 `launcher_data` 中**目标不存在**的
  文件递归补齐到新目录（**绝不覆盖已有文件**，跳过 `logs`）；同时把实际读取路径写入错误信息，
  便于日后诊断。正版凭据写入与读取的字段名经逐项核对确认一致，无需改动。
- **修复启动失败没有任何原因提示**：原实现以 `stdout: "ignore"` 丢弃标准输出，仅在进程退出后
  取一次 stderr 摘要。现改为 `stdout` / `stderr` 双流 pipe 接管并逐行实时推送，Java 版本不符、
  缺少 libraries 等异常栈会完整出现在「错误控制台」中；进程退出后按退出码给出「正常退出」或
  「异常退出（退出码 N）」摘要（附 stderr 末 6 行）并标注完整日志文件路径。
- **修复「创建视界」点击后毫无反应**：原实现中名称为空时直接静默 `return`，且没有任何前置
  校验提示、没有 pending 状态、没有结果反馈。现改为完整表单弹窗 + 三层保障：行内校验错误、
  提交期间的「正在创建…」禁用态、以及外壳 `horizon:result` 的成功 / 失败结果回推，
  任何一次点击都必有明确 UI 反馈，绝不静默失败。
- 修复首页在窄屏下右侧账号栏与启动区互相挤压的问题。
- 修复资源中心与视界详情在全屏 / 半屏之间的自适应：资源中心版本网格改用 `width: 100%` 的
  Flex 布局随窗口拉伸；视界详情的目录树与存档列表容器限制高度并内部滚动，内容不横向溢出；
  首页在窄屏下右侧账号栏自动下移堆叠。
- 修复 `client.jar` 等文件走镜像源时下载失败：源地址换算补全 `piston-data.mojang.com`
  域名（此前仅覆盖 `piston-meta`，导致镜像源下客户端 JAR 仍指向官方源）。
- 下载请求统一加入 `User-Agent: iGMLLauncher/26.4.1`，避免被 CDN 拦截。
- 单文件超时由 30s 收紧为「15s 空闲超时」（每收到数据块即重置），并新增速度下限判定
  （耗时 10s 后速度低于 1KB/s 即判为源过慢），作为自动换源的触发条件之一。

### 优化
- 废弃原图形关系图（SVG 节点连线 / 拖拽缩放）与「关联版本列表」：资源中心改为纯粹的
  「版本分类 + 版本卡片网格」，点击卡片直接进入一卡式安装弹窗，不再有中间详情栏。
- 废弃原「确认下载」模态弹窗，以及第 3 步的「下载源偏好」面板：下载源由引擎自动择优，
  全部配置收进一卡式弹窗；**第 4 步的「存放路径」不再是独立步骤，而是作为一卡式弹窗内的一行
  重新提供（默认回填当前根目录，可输入或浏览选择）**。
- 整体放大资源中心界面（面板内边距、标题、正文、按钮、版本卡片、搜索框与下拉框同步放大），
  大窗口下内容更舒展。
- 下载并发统一为 **25 并废除一切针对官方源的降级限制**：全局在途连接固定 25（由全局信号量
  统一约束，分片与单流共用配额，总量不会突破 25），单文件分片并发固定 25，
  Mojang 官方源与镜像源一视同仁，不再做任何限流。
- 大文件（≥2MiB）优先启用 25 分片并行下载：每片独立 `Range: bytes=<start>-<end>` 请求、
  独立句柄按文件偏移写入预分配的 `.part`，25 个分片由 `Promise.all` 同时发起（非串行），
  完成后流式重算整文件 SHA-1 校验；各分片进度合并为单一总进度回推界面。
- 不再依赖 `accept-ranges` 响应头来决定是否分片（该头在部分镜像缺失，是此前大文件退化为
  单流、下载极慢的主因）：改为只要文件够大即尝试分片，由每个分片的 206 响应实证判定；
  若服务器忽略 Range 返回 200 整文件，则自动回退单流下载，杜绝数据错位损坏。
- 清单已提供文件大小时跳过 `HEAD` 请求（版本详情与资源索引均含 `size`），
  数百个 libraries 与资源对象不再各发一次多余请求；任务结束后自动清理全部 `.part` 临时文件。
- 资源中心初始状态只显示版本分类卡片，不再显示任何步骤条与下载源 UI。
- 下载中心面板放大到 560px 宽（上限 `min(760px, calc(100vw - 48px))`）与 `min(70vh, 640px)` 高，
  改为左右两栏任务管理器布局，进度条、速度、剩余文件数与完成时间指示同步放大。
- 下载中心生命周期自动化：全部任务进入终态后（**完成 / 失败 / 用户主动取消一律同等对待**）
  立即逐个清除任务（连同外壳侧临时缓存一并清理）并收起面板、隐藏右下角悬浮图标，
  不再等待 3 秒、也不再因存在失败或取消任务而卡住不收尾；悬浮图标仅在下一次真正开始下载时
  重新出现；历史记录不受清理影响，下次仍可查看。
